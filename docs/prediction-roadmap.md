# 预测模块边界与路线图

首期**不实现预测模型**。`src/lib/prediction-contract.ts` 只定义输入校验和 `PredictionModel` 接口，防止未来训练代码直接依赖页面或供应商原始格式。

后续阶段建议：

1. 建立带 `asOf` 的特征快照，确保所有输入在预测时刻已经可得，避免前视偏差。
2. 按时间滚动切分训练、验证和测试集，纳入交易成本、基金跟踪误差和幸存者偏差。
3. 先实现朴素基线，再比较统计及机器学习模型；统一报告收益、回撤、换手率和稳定性。
4. 维护模型注册表，记录模型版本、代码提交、数据版本、特征版本、超参数、训练区间和评估结果。
5. 将离线训练、回测、模型审核与线上静态推理数据生成分离。任何预测输出都必须携带版本、生成时间、适用期限、不确定性和数据质量。
6. 建立漂移、缺失特征和回测退化监控；未通过门禁时显式停止发布，不回退到看似成功的旧预测。

真实 CN 数据只有日终单位净值，且发布时间可能晚于净值日期。未来特征构建必须同时使用 Quote `date` 与 `quality.collectedAt`，只允许纳入预测时刻已经发布的数据；不得把 11:00 刷新任务的运行时间误当作盘中价格时间，也不得用模拟市场数据训练或评估宣称基于真实行情的模型。

持仓特征必须使用报告期末、实际披露时间和采集时间三者中可验证的信息，避免在法定披露窗口内产生前视偏差。每日标的行情更新不等于仓位更新；回测不得用新行情重新解释尚未披露的组合变化。
